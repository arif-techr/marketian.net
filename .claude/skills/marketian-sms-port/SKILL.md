# Porting Marketian SMS from Laravel to Django

Goal: `sites/sms/api` (Django + DRF + Celery, PostgreSQL `sms-db`) answers **exactly** the same
`/api/v1` contract as `sites/sms/laravel`, so the Next.js panel in `sites/sms/web` keeps working.
Plan and task IDs: `Project Planning/08-sms-plan.md` (S0–S6). Not live, not in the root compose.

## Sources of truth
- `sites/sms/api/docs/contract.md` / `contract.json`: 248 endpoints with method, path, auth
  (public, session, staff, api_key, signature), permission/scope, flags, rate limit, Laravel action.
- `sites/sms/docs/11-laravel-api-reference.md`: response bodies and error codes.
- `sites/sms/laravel/app/...`: controllers, form requests (validation), services (the logic).
- `sites/sms/laravel/tests/`: the acceptance tests to port.

## Porting one endpoint (or one controller)
1. Find it in `contract.json`; open the Laravel controller action, its FormRequest and service.
2. **Port its feature tests first** from `laravel/tests/Feature/...` into the Django app's tests: same
   requests, same expected status, envelope and fields. Run them: they must fail.
3. Implement in the right app (accounts, orgs, contacts, messaging, billing, developers, support,
   system). Use the envelope from `common/envelope.py`: `ok()`, `fail()`, `raise ApiError(...)`.
4. Keep the contract: camelCase JSON fields, same status codes, same error codes (public: only add,
   never rename), `meta.requestId` on every JSON answer, validation messages shaped like Laravel's.
5. Honour the flags: `idempotent` (`Idempotency-Key`), `tenant` (active organisation), `feature X`,
   `verified.email`, and the rate limit named in the contract.
6. Tests pass on SQLite **and** PostgreSQL (money and queues use row locks).
7. Set `"done": true` for the endpoint in `contract.json`; the test run prints
   `[contract] N of 248 endpoints done`. Update the S-task line in 08-sms-plan.md when a task finishes.

## Decided differences from Laravel
- Sign-in is the Marketian account (OIDC) only: no passwords, no Google, no phone sign-in. A personal
  organisation is created at first sign-in; invitations by email. `accounts.User` has no password
  or last_login columns.
- MariaDB → PostgreSQL: rewrite MySQL-only queries (reports, `JSON_*`, `GROUP_CONCAT`, date functions).
- Money is `DECIMAL(14,4)` as `Decimal`. Wallet changes in a transaction with `select_for_update`;
  a balance must never go negative under concurrency (test it).
- Status values stay upper case (`ACTIVE`, `SUPER_ADMIN`). Table names stay the Laravel ones.
- Models were generated by `tools/generate_models.py`, then edited by hand: **never rerun it** over
  them; change models directly and make migrations.
- The SMS gateway is Automas (adapter unverified): tests use the mock provider; never send real SMS
  from tests. Real test SMS only to the user's own numbers, at S6.2.
